# Справочник по схеме меток

Этот документ определяет соответствие между лингвистическими таксономиями ошибок, обработчиками synterr и выходным форматом GECToR.

## Трёхуровневая схема

```
┌─────────────────────────────────────────────────────────────────────┐
│                     ТАКСОНОМИЯ RLC (38 тегов)                       │
│   Лингвистическая классификация причин ошибок                       │
│   Gov, AgrCase, AgrNum, Asp, Infl, Lex, Miss, Extra, ...           │
└─────────────────────────────┬───────────────────────────────────────┘
                              │ соответствует
                              ▼
┌─────────────────────────────────────────────────────────────────────┐
│                   ОБРАБОТЧИКИ SYNTERR                               │
│   Модули реализации                                                 │
│   spelling, noun_case, paronym, word_omission, ...                 │
└─────────────────────────────┬───────────────────────────────────────┘
                              │ выводит
                              ▼
┌─────────────────────────────────────────────────────────────────────┐
│                   ФОРМАТ GECTOR                                     │
│   Метка детекции + тег исправления                                  │
│   SPELL/MORPH/OTHER + $REPLACE/$TRANSFORM/$APPEND/$DELETE          │
└─────────────────────────────────────────────────────────────────────┘
```

## Выходной формат GECToR

### Метки детекции

| Метка | Описание | Типы ошибок |
|-------|----------|-------------|
| `CORRECT` | Нет ошибки в этой позиции | — |
| `SPELL` | Орфографическая ошибка | `Ortho`, `Misspell`, `Graph` |
| `MORPH` | Морфологическая ошибка | `Infl`, `Agr*`, `Gov`, `Asp`, `Tense` |
| `PUNCT` | Пунктуационная ошибка | (не реализовано) |
| `OTHER` | Лексические, структурные и прочие | `Lex`, `Prep`, `Conj`, `Miss`, `Extra`, `WO` |

### Теги исправления

| Шаблон тега | Описание | Когда используется |
|-------------|----------|-------------------|
| `$KEEP` | Токен корректен | Нет ошибки |
| `$DELETE` | Удалить этот токен | `Extra` (вставленное слово-паразит) |
| `$REPLACE_слово` | Заменить на слово | `Lex`, `Prep`, `Conj` |
| `$TRANSFORM_CASE_X` | Изменить падеж на X | `Infl` (падеж), `AgrCase`, `Gov` |
| `$TRANSFORM_NUM_X` | Изменить число на X | `Infl` (число), `AgrNum` |
| `$TRANSFORM_GENDER_X` | Изменить род на X | `AgrGender` |
| `$TRANSFORM_TENSE_X` | Изменить время на X | `Tense` |
| `$TRANSFORM_PERSON_X` | Изменить лицо на X | `AgrPers` |
| `$APPEND_слово` | Добавить слово после | `Miss` (пропущенное слово) |
| `$MERGE_слово` | Объединить со следующим | (редко) |

### Формат выходной строки

```
$STARTSEPL|||SEPR$KEEP:CORRECT ПервоеСловоSEPL|||SEPR$REPLACE_верное:SPELL ашибкаSEPL|||SEPR...
```

Структура:
- `$START` — маркер начала предложения
- `SEPL|||SEPR` — разделитель токенов
- `$TAG:CATEGORY слово` — тег исправления, категория детекции, искажённый токен

## Ошибки, меняющие длину

### Проблема

Большинство ошибок **сохраняют число токенов**: они искажают слово, но не меняют количество токенов.

```
Оригинал:   [Я] [иду] [в] [школу]     # 4 токена
Искажённый: [Я] [иду] [в] [школы]     # 4 токена (ошибка падежа школу→школы)
```

**Ошибки, меняющие длину**, добавляют или удаляют токены:

```
# Пропуск (Miss): удаление токена
Оригинал:   [Я] [иду] [в] [школу]     # 4 токена
Искажённый: [Я] [иду] [школу]         # 3 токена (предлог удалён)

# Вставка (Extra): добавление токена
Оригинал:   [Он] [читает] [книгу]     # 3 токена
Искажённый: [Он] [вот] [читает] [книгу]  # 4 токена (вставлено слово-паразит)
```

### Проблема сбоя индексов

Если удалить токен с индексом 2, все последующие индексы сдвигаются:

```
До:     [0:Я] [1:иду] [2:в] [3:школу]
Удаляем idx 2
После:  [0:Я] [1:иду] [2:школу]  # "школу" переместилось с 3→2!
```

Если мы уже записали, что ошибка на индексе 3, это теперь неверно.

### Решение: применять ошибки, меняющие длину, последними

Пайплайн:
1. Сначала применяет все **сохраняющие длину** ошибки (орфография, падеж и т.д.)
2. Затем применяет **меняющие длину** ошибки (пропуск, вставка)
3. Только одна меняющая длину ошибка на предложение (для простоты)

### Объявление обработчика

Обработчики должны объявлять, меняют ли они длину:

```python
class WordOmissionHandler:
    name = "word_omission"
    category = "OTHER"
    changes_length = True   # ← Обязательно для Miss/Extra

class SpellingErrorHandler:
    name = "spelling"
    category = "SPELL"
    changes_length = False  # ← По умолчанию, можно опустить
```

### Теги исправления для ошибок, меняющих длину

**Пропуск (`Miss`)**: исправление — ДОБАВИТЬ пропущенное слово

```python
# "Я иду школу" ← пропущено "в"
# Токен ПЕРЕД местом, где должно быть "в", получает тег исправления
# Токен "иду" получает: $APPEND_в:OTHER

ErrorResult(
    error_type="word_omission",
    category="OTHER",
    start_idx=1,          # индекс "иду" (слово перед пропуском)
    end_idx=1,
    original="в",         # что было удалено
    corrupted="",         # ничего (слово исчезло)
    fix_tag="$APPEND_в",  # исправление = добавить "в" после этой позиции
)
```

**Вставка (`Extra`)**: исправление — УДАЛИТЬ вставленное слово

```python
# "Он вот читает книгу" ← "вот" лишнее
# Вставленный токен получает: $DELETE:OTHER

ErrorResult(
    error_type="word_insertion",
    category="OTHER",
    start_idx=1,          # индекс вставленного "вот"
    end_idx=1,
    original="",          # там ничего не было
    corrupted="вот",      # что было вставлено
    fix_tag="$DELETE",    # исправление = удалить этот токен
)
```

### Что можно пропускать/вставлять

**Цели для пропуска** (служебные слова, которые учащиеся часто забывают):
- Предлоги: в, на, с, к, из, от, по, за, о, у
- Частицы: бы, ли, же, не, ни
- Союзы: и, а, но, что, чтобы, если, когда
- Возвратный суффикс: -ся (как отдельный токен после гласной)

**Цели для вставки** (слова-паразиты, которыми учащиеся злоупотребляют):
- Дискурсивные маркеры: вот, ну, так, ведь, же
- Хеджи: как бы, типа, значит, это
- Повторы: дублирование соседнего слова

## Логика назначения категории

```python
def get_category(handler_name: str) -> str:
    """Сопоставить обработчик с категорией детекции."""

    SPELL_HANDLERS = {"spelling"}

    MORPH_HANDLERS = {
        "noun_case", "noun_number",
        "adj_case", "adj_number", "adj_gender",
        "verb_person_number", "verb_tense",
        "agr_case", "agr_number", "agr_gender", "agr_person",
        "government", "aspect", "reflexive", "voice",
    }

    PUNCT_HANDLERS = {"punctuation"}  # не реализовано

    # Всё остальное — OTHER
    # Включает: paronym, preposition, conjunction,
    #           word_omission, word_insertion, word_order

    if handler_name in SPELL_HANDLERS:
        return "SPELL"
    elif handler_name in MORPH_HANDLERS:
        return "MORPH"
    elif handler_name in PUNCT_HANDLERS:
        return "PUNCT"
    else:
        return "OTHER"
```
