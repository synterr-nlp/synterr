# План реализации synterr

Этот документ описывает оставшиеся типы ошибок для реализации, необходимые лингвистические ресурсы и технические особенности.

## Обзор архитектуры

synterr использует подход **инверсии правил**:

```
┌─────────────────┐     ┌─────────────────┐     ┌─────────────────┐
│  Поиск правила  │ →   │    Инверсия     │ →   │ Вывод + метка   │
│  "Что верно"    │     │ "Сделать ошибку"│     │  Формат GECToR  │
└─────────────────┘     └─────────────────┘     └─────────────────┘
```

Каждый `ErrorHandler` реализует:
- `can_apply(tokens, idx)` — Проверить, применим ли этот тип ошибки в позиции
- `apply(tokens, sentence, idx, modified)` — Сгенерировать искажённую форму

Категории ошибок соответствуют меткам детекции: `SPELL`, `MORPH`, `PUNCT`, `OTHER`

## Что нужно реализовать

### Приоритет 1: Лексические ошибки (depparse не нужен)

#### 1.1 Смешение паронимов (`Lex`)
- **Ресурс**: `data/russian/paronyms.json` ✅ Уже создан
- **Категория**: OTHER
- **Реализация**: Найти слово в словаре паронимов, заменить на пару

```python
# Пример
"одеть пальто" → "надеть пальто"  # смешение одеть/надеть
"эффектный приём" → "эффективный приём"  # эффектный/эффективный
```

#### 1.2 Замена предлогов (`Prep`)
- **Нужен ресурс**: Группы семантически близких предлогов
- **Категория**: OTHER
- **Реализация**: Заменить на семантически близкий предлог

```python
PREP_GROUPS = {
    "spatial": ["в", "на", "у", "около", "возле"],
    "temporal": ["в", "на", "за", "через"],
    "causal": ["из-за", "благодаря", "вследствие"],
}
# "в комнате" → "на комнате" ❌
```

#### 1.3 Замена союзов (`Conj`)
- **Нужен ресурс**: Пары смешиваемых союзов
- **Категория**: OTHER

```python
CONJ_CONFUSIONS = {
    "а": ["но", "и"],
    "что": ["чтобы"],
    "потому что": ["поэтому"],  # перестановка причины/следствия
}
```

#### 1.4 Ошибки с частицами
- **Категория**: OTHER
- **Реализация**: Удалить частицы (бы, ли, же) или вставить в неверное место

### Приоритет 2: Ошибки согласования (требуется `--depparse`)

Эти ошибки требуют синтаксического разбора для поиска связи управляющий-зависимый.

#### 2.1 Согласование прилагательного с существительным (`AgrCase`, `AgrGender`, `AgrNum`)
- **Синтаксическое отношение**: `amod` (адъективный модификатор)
- **Категория**: MORPH
- **Реализация**: Найти прилагательное при существительном, изменить его так, чтобы не согласовывалось

```python
def can_apply(tokens, idx):
    token = tokens[idx]
    return token.pos == "ADJ" and token.dep_rel == "amod"

def apply(tokens, sentence, idx, modified):
    adj = tokens[idx]
    head_noun = tokens[adj.head_idx]

    # Получить признаки существительного
    noun_case = head_noun.features.get("Case")
    noun_gender = head_noun.features.get("Gender")

    # Сгенерировать прилагательное с НЕВЕРНЫМ падежом/родом
    wrong_case = random.choice([c for c in CASES if c != noun_case])
    wrong_form = inflect_adj(adj.lemma, wrong_case, noun_gender, ...)

    return ErrorResult(...)
```

#### 2.2 Согласование подлежащего и сказуемого (`AgrNum`, `AgrPers`)
- **Синтаксическое отношение**: `nsubj` (именное подлежащее)
- **Категория**: MORPH
- **Реализация**: Найти подлежащее глагола, изменить глагол на неверное лицо/число

```python
# "Дети играют" → "Дети играет" ❌ (мн.ч. подлежащее + ед.ч. глагол)
# "Я читаю" → "Я читает" ❌ (1 л. подлежащее + 3 л. глагол)
```

#### 2.3 Согласование предиката
- **Синтаксическое отношение**: `nsubj` со связкой или кратким прилагательным
- **Категория**: MORPH

```python
# "Книга была интересная" → "Книга была интересное" ❌
```

### Приоритет 3: Ошибки управления (требуется `--depparse` + ресурс)

#### 3.1 Глагольное управление (`Gov`)
- **Нужен ресурс**: `GOV_DICT = {лемма_глагола: (предлог, падеж)}`
- **Синтаксическое отношение**: `obj`, `iobj`, `obl`
- **Категория**: MORPH

```python
GOV_DICT = {
    "помогать": (None, "Dat"),      # помогать кому
    "ждать": (None, "Gen"),          # ждать кого/чего
    "смотреть": ("на", "Acc"),       # смотреть на кого
    "думать": ("о", "Prep"),         # думать о чём
    "интересоваться": (None, "Ins"), # интересоваться чем
}

# "помогать другу" → "помогать друга" ❌ (Дат → Род)
```

**Источник для GOV_DICT**: Розенталь «Управление в русском языке» или извлечь из ruscorpora.ru

#### 3.2 Управление предлогов (`Prep` + `Gov`)
- **Нужен ресурс**: `PREP_CASE = {предлог: [допустимые_падежи]}`
- **Категория**: MORPH

```python
PREP_CASE = {
    "в": ["Acc", "Prep"],  # в школу (Вин), в школе (Предл)
    "на": ["Acc", "Prep"],
    "с": ["Gen", "Ins"],   # с горы (Род), с другом (Твор)
    "за": ["Acc", "Ins"],
    "под": ["Acc", "Ins"],
}

# Использовать неверный падеж для контекста предлога
# "в школе" (место) → "в школу" ❌ (падеж направления в контексте места)
```

### Приоритет 4: Ошибки в глагольных категориях

#### 4.1 Смешение видов (`Asp`)
- **Нужен ресурс**: `ASP_PAIRS = {НСВ: СВ, СВ: НСВ}`
- **Нужен ресурс**: `ASP_TRIGGERS = {глагол-триггер: требуемый_вид}`
- **Категория**: MORPH

```python
ASP_PAIRS = {
    "читать": "прочитать",
    "писать": "написать",
    "делать": "сделать",
    "говорить": "сказать",
    # ... ~2000 пар из словарей РКИ
}

ASP_TRIGGERS_NSV = ["начать", "начинать", "продолжать", "кончить", "бросить"]
# После этих глаголов инфинитив должен быть НСВ

# "Он начал читать" → "Он начал прочитать" ❌
```

**Источник для ASP_PAIRS**: Русский Викисловарь, учебники РКИ (Лазарева, Чернышов)

#### 4.2 Ошибки с возвратностью (`Refl`)
- **Категория**: MORPH
- **Реализация**: Неверно добавить/убрать -ся/-сь

```python
# "Дверь открылась" → "Дверь открыла" ❌ (пропущен возвратный суффикс)
# "Я мою руки" → "Я моюсь руки" ❌ (лишний возвратный суффикс)
```

#### 4.3 Ошибки залога (`Passive`)
- **Категория**: MORPH
- **Реализация**: Смешение актива ↔ пассива

### Приоритет 5: Структурные ошибки (меняют длину)

Эти обработчики устанавливают `changes_length = True` и требуют особой обработки в пайплайне.

#### 5.1 Пропуск слова (`Miss`)
- **Категория**: OTHER
- **Реализация**: Удалить служебное слово (предлог, частицу, союз)
- **Тег исправления**: `$APPEND_слово`

```python
# "Я иду в школу" → "Я иду школу" ❌
# Исправление: $APPEND_в

def apply(tokens, sentence, idx, modified):
    # Удалить токен в позиции idx
    del sentence[idx]
    return ErrorResult(
        fix_tag=f"$APPEND_{tokens[idx].text}",
        ...
    )
```

#### 5.2 Вставка лишнего слова (`Extra`)
- **Категория**: OTHER
- **Реализация**: Вставить слово-паразит или дублировать
- **Тег исправления**: `$DELETE`

```python
FILLERS = ["вот", "ну", "так", "это", "значит"]

# "Он читает книгу" → "Он вот читает книгу" ❌
# Исправление: $DELETE
```

#### 5.3 Порядок слов (`WO`)
- **Категория**: OTHER
- **Реализация**: Неуместно поменять местами соседние слова
- **Примечание**: В русском свободный порядок слов, поэтому это тонкий момент

## Технические замечания

### Синтаксический разбор (Dependency Parsing)

Включается флагом `--depparse`. Добавляет ~40% накладных расходов, но необходим для ошибок согласования/управления.

```bash
synterr generate --lang ru --depparse -i corpus.txt -o out.edits
```

В коде:
```python
config = GenerationConfig(use_depparse=True)
# или
config = GenerationConfig.from_preset("ru", "balanced", use_depparse=True)
```

### Обработчики, меняющие длину

Обработчики, которые добавляют/удаляют токены, должны устанавливать `changes_length = True`:

```python
class WordOmissionHandler:
    name = "word_omission"
    category = "OTHER"
    changes_length = True  # Важно!
```

Пайплайн применяет их последними, чтобы избежать сбоя индексов.

### Регистрация обработчиков

Добавляйте новые обработчики в `src/synterr/languages/russian/errors/__init__.py`:

```python
from synterr.languages.russian.errors.lexical import (
    ParonymHandler,
    PrepositionHandler,
)

ALL_HANDLERS = [
    SpellingErrorHandler(),
    NounCaseHandler(),
    # ... существующие ...
    ParonymHandler(),      # Новый
    PrepositionHandler(),  # Новый
]
```

Каждому обработчику нужны тесты в `tests/test_languages/test_russian/`:

## Рекомендуемый порядок реализации

1. **Лексические ошибки** (паронимы, предлоги, союзы) — Без depparse, просто реализовать
2. **Структурные ошибки** (пропуск, вставка) — Меняют длину, но логика простая
3. **Ошибки согласования** — Требуют depparse, сложнее
4. **Ошибки управления** — Требуют depparse + создание GOV_DICT
5. **Ошибки вида** — Требуют создания словаря видовых пар

Начинай с того, для чего есть ресурсы (паронимы ✅), затем создавай ресурсы по ходу работы.
